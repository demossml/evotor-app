# Установка 6.7 Coffee на Эвотор

Package: `ru.sixthcup.evotor`  
VersionCode: `53`  
VersionName: `2.3.2-evotor-catalog`

## 1. Сборка

В Android Studio открой проект `evotor-app-main` и собери Debug APK.

Для signed QR при сборке передай реальные значения публичного ключа сервера:

```bash
./gradlew :app:assembleDebug \
  -PSERVER_PUBLIC_KEY=<base64url-ed25519-public-key> \
  -PSERVER_KEY_ID=<key-id> \
  -PCUPS_FOR_FREE=5
```

Секретный приватный ключ сервера в Android-проект не попадает.

## 2. Установка

Установить APK можно через портал Эвотора в тестовую версию либо через ADB в режиме разработчика.

Для ADB:

```bash
adb connect <IP_ТЕРМИНАЛА>:5555
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 3. Что должно быть на терминале

Сначала backend 6.7 должен синхронизировать торговую точку и номенклатуру с Evotor Cloud.
Эвотор затем доставляет товары на терминал штатным механизмом.

Приложение 6.7 **не требует отдельной загрузки собственного каталога** и не имеет хардкодного `Catalog.kt`.

## 4. Рабочий сценарий

1. В админке 6.7 создайте товар: название, цена, рецепт, схему добавок и loyalty-флаги.
2. Дождитесь Cloud sync или запустите синхронизацию торговой точки из вкладки «Эвотор».
3. Проверьте, что у товара появился `evotorUuid`.
4. После доставки товара на терминал откройте меню добавления позиции Эвотора и выберите **6.7 Coffee**.
5. APK читает реальную локальную номенклатуру Эвотора, находит товар по UUID и показывает рецепт/добавки из `ProductExtra`.
6. Нажмите «Добавить в чек Эвотора» — в чек возвращается обычная `Position` с существующим Evotor product UUID.
7. Перед продажей бариста может сканировать signed QR гостя или ввести короткий номер карты.
8. После фискального `SELL` backend через poll обрабатывает `extras.sc`.

## 5. Важные ограничения

- APK не фискализирует чек самостоятельно.
- APK не считает loyalty как источник истины.
- Backend не создаёт второй Evotor product при каждом sync: первый CREATE получает UUID от Cloud, дальше используется PUT по сохранённому UUID.
- Если ответ первого CREATE потерян, backend сначала ищет уже созданный товар по `articleNumber=sc-<localProductId>` и только потом создаёт новый.
- Рецепты и топпинги для кассы приходят через `ProductExtra`, а не через хардкод каталога.

## 6. Финальная проверка на реальном ST5

Нужно проверить физически:

1. создать новую позицию в админке;
2. увидеть один новый товар в Evotor Cloud;
3. дождаться появления его на терминале;
4. открыть 6.7 Coffee из меню Эвотора;
5. увидеть название/цену/рецепт/добавки;
6. добавить товар в чек;
7. применить QR или ручной card code;
8. закрыть продажу;
9. получить SELL через Cloud API;
10. убедиться, что `extras.sc.c` содержит правильный token или short code;
11. проверить начисление loyalty;
12. повторно запустить sync и убедиться, что новый товар не дублируется.
