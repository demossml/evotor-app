# CHANGELOG — редизайн кассового UI (v75, 4.6.0-cashier-ui)

Эвотор ST5 (≈5″, портрет). Каталог по-прежнему из Inventory Эвотор, цена = PRICE_OUT (копейки/100),
контракт `extras.sc`, подарочный стакан, loyalty resolve, `usesCleartextTraffic=false` — **не менялись**.

## Версия
- `versionCode` 73 → **75**, `versionName` `4.5.1-photos` → **4.6.0-cashier-ui**.
- `+ androidx.recyclerview:recyclerview:1.3.2` (раньше приходил транзитивно через Material; теперь явно).

## Фаза A — раскладка и «тормоза»
| Было (причина) | Стало |
|---|---|
| Каждая буква поиска и каждый чип пересобирали **всё дерево** (`host.removeAllViews()` + сотни view) | Каталог — `RecyclerView` + `ListAdapter` + `DiffUtil` (ключи `p:uuid`), `notifyDataSetChanged` нигде нет; чипы создаются один раз, при выборе меняется только стиль; поиск с debounce 180 мс |
| Все строки создавались сразу (eager) | Только видимые ViewHolder'ы, слушатели ставятся один раз в конструкторе, `itemAnimator = null`, `setHasFixedSize`, кэш 8 ячеек |
| Каталог ждал сеть (`CatalogApi.fetch`, до 12 с) до первого показа | **Две фазы**: Inventory (локально) → показ сразу; backend-обогащение (фото, топинги, upsell) догружается и применяется diff'ом |
| Нижняя панель 2 строки + отступы (~130 dp съедали список) | Одна строка 52 dp: «Корзина · N · сумма» + «К оплате» |
| Верхняя панель: карта 56 dp + «Ещё» 56 dp + поиск 48 dp в прокручиваемой части | Одна строка 48 dp (карта/лояльность + «Ещё»); поиск и чипы **закреплены** над списком |
| Нет учёта системных отступов, контент «уезжал за края» | `ViewCompat.setOnApplyWindowInsetsListener` (systemBars + displayCutout) на корне; все тексты `maxLines` + `ellipsize`, строки на `weight`, чипы в горизонтальном скролле |
| Рецепт «i» у каждой строки | «i» только если рецепт известен; иначе долгий тап (загрузка рецепта по требованию, как раньше) |

## Фаза B — фото
- `ThumbLoader` переписан: память (LruCache ≈1/12 кучи) → **диск** (`cacheDir/thumbs`, WebP ≤288 px, лимит 24 МБ, чистка старых при старте) → сеть (только `https`, таймауты 4/8 с, потолок 2 МБ, декод с `inSampleSize`).
- Отмена при переиспользовании ячейки (`onViewRecycled` → `ThumbView.release()`), пропуск отменённых задач в очереди, negative-cache неудач на 5 мин, один скачивающий поток на URL.
- `ThumbView` — одна лёгкая view (круг/скругление через `BitmapShader`, инициалы-заглушка), вместо `FrameLayout+TextView+ImageView+clipToOutline` на строку.
- Размеры: список 52 dp (запрос 128 px), «Фокус» 120×88 dp (запрос 288 px).
- Premium-заглушка, если у товара нет `imageUrl`: круг цвета brand-tint + инициалы бренд-цветом.

## Фаза C — «Фокус» и комбо
- Горизонтальная карусель карточек 136 dp (фото, название ≤2 строк, цена). Показывается на «Всё» без поиска.
- Кто попадает в «Фокус»: метка `#focus` или `#combo` в описании товара Эвотор, либо ` + ` (с пробелами) в названии. Меток нет — блока нет (прежний «угадыватель» по первым напиткам убран).
- Комбо в API нет → heuristic + метки (см. `data/ProductMarkers.kt`). **Модель цены:** в чек всегда уходит PRICE_OUT; метка `#old=250` лишь рисует старую цену зачёркнутой, а цену по акции — красной. Скидок приложение не считает.
- Метки вырезаются из текста рецепта (`ProductMarkers.cleanDescription`); `FreeCupRules` читает «сырое» описание, `#cup/#nocup` работают как раньше.
