# Отчёт: устранение обхода «Повторить» и проверка боевого пути чека

Версия: **5.2.18-repeat-receipt-safety / versionCode 144**
База: локальный коммит `549b51c` (5.2.17). Пуш и публикация APK не выполнялись.

## 1. Какие обходы устранены

| Обход | Было | Стало |
|---|---|---|
| «Повторить» копировал прошлый чек целиком | `Cart.repeatLast()` клал в корзину все строки, включая платное молоко/добавки и напитки с обязательной схемой молока | `Cart.repeatLast()` **удалён**; `Cart.lastOrderLines()` только читает, решение принимает `RepeatOrder.plan`, повтор идёт через `openProduct` |
| Платные опции восстанавливались без проверки uuid | строки с `optionId` возвращались как обычные | `Skip` — опция выбирается заново в окне, где проверяются `available`/`evotorUuid` |
| Товар, удалённый из каталога, восстанавливался | возвращался как позиция | `Skip` («товара нет в каталоге»), затем тот же контроль на оплате в `ReceiptValidator` |
| Комбо собиралось построчно | позиции комбо возвращались по одной | `Skip` — комбо собирается заново |
| Синтетические `mod:`-строки | отфильтровывались, но логика дублировалась | `Skip` по общему правилу `Cart.isSellable` |
| Сборка строк корзины жила только внутри `MainActivity` | тесты не могли проверить боевой путь | вынесена в чистый `CartLines.of(...)`, вызывается из `MainActivity` |
| Позиции чека собирались прямо в `SellLauncher` | решение «что и по какой цене» не тестировалось | вынесено в чистый `ReceiptPlan.plan(...)`, вызывается из `SellLauncher` |

## 2. Как теперь работает «Повторить»

`MainActivity.repeatLastOrder()`:

1. берёт `Cart.lastOrderLines()` (только чтение сохранённого прошлого чека);
2. строит план через `RepeatOrder.plan(lastOrder, products, noConfigConfirmed)`:
   - товар, для которого сервер уже подтвердил «схем нет» → восстанавливается (`Restore`);
   - обычный товар с непроверенной конфигурацией, с обязательным молоком/объёмом или при недоступном сервере → `NeedsChoice`;
   - строка-опция (`optionId != null`), комбо, `mod:…`, отсутствующий в каталоге товар → `Skip` с причиной;
3. восстанавливает только `Restore`, складывает `NeedsChoice` в очередь `repeatQueue`
   и открывает первую позицию через `openProduct` — тот же путь, что при нажатии на плитку
   (запрос конфигурации → окно выбора объёма/молока/добавок либо прямое добавление при
   подтверждённом «схем нет»);
4. после фактического добавления (`openProductLegacy` или «В чек» в окне) вызывается
   `openNextRepeatItem()` — следующая позиция очереди.

Если ничего не восстановимо, касса пишет причину («Повторить нельзя: … — товара нет в каталоге»),
а не добавляет позицию молча.

## 3. Какой код реально формирует позиции чека

Единый путь (все звенья — боевые):

```
showItemSheet «В чек»                                  MainActivity
  → CartLines.of(variant, chosenToppings, mods, sig, qty)   data/CartLines.kt   (чистый)
  → Cart.add
  → (оплата) ReceiptValidator.validate                    data/ReceiptValidator.kt
  → SellLauncher.openSellReceipt                          sell/SellLauncher.kt
      → FiscalLines.build(lines, split)                   data/FiscalDiscount.kt
      → ReceiptPlan.plan(fiscalLines, terminal)           sell/ReceiptPlan.kt  (чистый)
      → Position.Builder.newInstance(item, qty).setPrice(...)
        (+ setPriceWithDiscountPosition, только если цена ниже)
```

Правила, которые теперь проверяются на этом пути:

- основной товар — объём (`variant.uuid`), ровно одна позиция, без дубля;
- бесплатное обычное молоко (`zeroOption`/`isFree`) — не создаёт позицию, остаётся в рецепте;
- платное молоко и добавки — отдельные позиции по `evotorUuid` из каталога;
- `sendToReceipt = false` — в чек не попадает;
- несколько добавок — по позиции на каждую, без склейки и дублей;
- цена — из номенклатуры терминала (`InventoryApi.getProductByUuid`), расхождение с корзиной
  фиксируется в `priceMismatch` (лог `price_mismatch`);
- `mod:…`-позиции и пустые uuid не продаются (`skippedSynthetic`);
- количество переносится в каждую позицию.

## 4. Тесты боевого пути

`app/src/test/java/ru/sixthcup/evotor/sell/ReceiptPlanTest.kt` — 12 тестов, вызывают
`ConfigOptsMapper` → `CartLines` → `FiscalLines` → `ReceiptPlan` (тот же код, что на кассе):

1. основной товар одной позицией;
2. бесплатное молоко не создаёт позицию;
3. платное молоко — отдельная позиция с uuid и ценой каталога;
4. добавка — отдельная позиция;
5. несколько добавок — по позиции на каждую, без дублей;
6. `sendToReceipt=false` — опция вне чека;
7. количество применяется ко всем позициям;
8. цена берётся из номенклатуры терминала (и `priceMismatch`);
9. цена со скидкой — только когда ниже;
10. синтетическая добавка отбрасывается;
11. полный путь «конфигурация → окно → корзина → позиции чека»;
12. полный путь с бесплатным молоком — одна позиция, молоко в рецепте.

`app/src/test/java/ru/sixthcup/evotor/data/RepeatOrderTest.kt` — 8 тестов:

1. напиток с обязательным молоком — `NeedsChoice`, платное молоко в `Skip`;
2. недоступная конфигурация — без молчаливого восстановления;
3. товар удалён из каталога — `Skip`, план пустой;
4. подтверждённое «схем нет» — строка восстанавливается;
5. строки-опции не восстанавливаются даже для простого товара;
6. комбо-группа не восстанавливается построчно;
7. синтетическая позиция отбрасывается;
8. один товар не попадает в очередь дважды.

## 7. Оставшиеся ограничения

1. **Терминал Эвотор не проверялся**: реальный чек (обычное молоко, платное молоко, добавки,
   `priceWithDiscountPosition`) и `logcat -s SC_TOP`/`SellLauncher` — только на кассе.
2. **Backend-маршрут конфигурации** не проверялся; при 404/недоступности касса открывает окно
   и не добавляет молча.
3. **Повтор по одной позиции**: очередь открывает карточки последовательно; если кассир закроет
   окно без выбора, позиция просто не восстановится (фантомных строк нет, но и предупреждения
   о незавершённом повторе нет).
4. **UI-тестов нет** (нет Robolectric/Espresso): проверены чистые звенья боевого пути, сам клик
   «В чек»/«Повторить» тестами не покрыт.
5. `Cart.lastOrderLines()` читает SharedPreferences — тестами покрыт разбор строк
   (`decode` через `CartLine`-конструкторы) и план `RepeatOrder`, но не хранилище.
6. Ветка «позиция не найдена в номенклатуре терминала» по-прежнему отправляет позицию
   «ручной» строкой (как было до этих правок) — поведение сохранено осознанно.
7. Изменения **не отправлены** в GitHub, APK **не опубликован**.
