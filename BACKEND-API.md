# Что добавить в бэкенд (6.7 Coffee · касса Эвотор)

База: `https://app.67coffee.ru`. Заголовок Authorization подставляет Evotor Cloud (как сейчас).
Все новые методы — `GET/POST /api/devices/...`. Общие правила:
- Ошибка = HTTP 4xx/5xx + `{ "ok": false, "error": "<код>", "message": "<для человека>" }`.
- Время — Unix-секунды UTC; деньги — рубли целым числом (`...Rub`) или копейки (`...Kopecks`), как в существующем `catalog`.
- Приложение **ничего не рисует из воздуха**: пока метод не ответил — экран показывает «загрузка», при ошибке — «не удалось загрузить + повторить», при пустом ответе — пустое состояние. Поэтому каждый метод должен честно отдавать пусто/ошибку, а не заглушку.
- Идентификация кассы: заголовки `X-Evotor-Store-Uuid` (есть) и `X-Evotor-Device-Uuid` (добавить), если нужно разделять точки.

## A. Уже работает (не менять контракт)
| Метод | Назначение |
|---|---|
| `GET /api/devices/catalog` | Товары, категории, топпинги, апсейл |
| `POST /api/devices/loyalty/resolve` | Карта гостя по QR/коду → чашки, бонусы, подарок |

## B. Доработки каталога (для 1:1 с дизайном)
`GET /api/devices/catalog` — добавить в `products[]` (все поля необязательные):
- `imageUrl` — **PNG с прозрачным фоном** для напитков (приложение рисует его «вписанным» в плитку 96/120/126 dp на градиенте; непрозрачное фото тоже работает, но обрезается по краям). Рекомендуем 600×480.
- `kind`: `"drink" | "food" | "combo"`; для `combo` — `comboDrinkProductId`, `comboFoodProductId`, `comboDiscountRub` (фиксированная скидка комбо; в чек уходит через DiscountIntegrationService).
- `flag`: `"new" | "hit" | null` — бейдж на плитке.
- `oldPriceRub` — зачёркнутая цена.
- `categoryOrder` (в `categories[]`) — порядок чипсов.

## C. Лояльность (резерв — как в BACKEND-METHODS.md)
- `POST /api/devices/loyalty/reserve` — `{code, storeUuid, lines[]}` → `{reservationId, expiresAt, freeAvailable, maxCashbackKopecks}`. Держит подарок/потолок кэшбэка на время оформления (TTL 10 мин).
- `POST /api/devices/loyalty/cancel-reserve` — `{reservationId}`; идемпотентно.
- **Обработчик чека продажи** (Cloud webhook или опрос документов): взять `extras.sc` (код, reservationId, cashbackKopecks), идемпотентно по `documentUuid`, списать резерв, начислить чашки/кэшбэк. Сумму скидки с терминала не считать источником истины — пересчитать на сервере. Чашки и бонусы на экране «Чек пробит» приложение не обещает — они обновятся после синхронизации чека.

## D. Поиск гостя (экран «Гость»: ввод по номеру)
`POST /api/devices/loyalty/lookup`
```json
{ "query": "+7 900 123-45-67" }          // телефон или короткий номер карты
→ { "ok": true, "matches": [ { "cardCode": "...", "name": "Анна", "maskedPhone": "+7 ••• ••• 45 67" } ] }
```
0 совпадений → `{ "ok": true, "matches": [] }` (приложение покажет «не найдено»). Дальше код карты идёт в существующий `resolve`. Не отдавать полный телефон — только маску.
`GET /api/devices/loyalty/last-card` (необязательно) — последняя карта на этой кассе для строки «последняя карта».

## E. Смена (экран «Смена») — контракт, который уже вызывает приложение 4.9.1
Фискальное состояние смены (открыта/закрыта, номер) приложение берёт **у самого Эвотора**. Бэкенд отдаёт только то, чего у Эвотора для сторонних приложений нет.
Правила для всех методов: 200 + JSON; пусто = пустой массив/`null`, а не заглушка; 4xx/5xx → `{ "ok": false, "message": "<для человека>" }` (текст показывается на экране). 404 приложение показывает как «Сервер пока не поддерживает этот раздел» — можно выкатывать методы по одному.
Данные — **только своя точка и текущий сотрудник** (точка определяется Evotor Cloud по устройству).

### `GET /api/devices/timesheet?from=2026-10-01&to=2026-10-31`
Смены текущего сотрудника за период (приложение запрашивает целый месяц, листает месяцы назад/вперёд).
```json
{ "days": [ { "date": "2026-10-18", "status": "work|off|vacation|sick", "from": "08:00", "to": "16:00", "note": "необязательно" } ] }
```
Нет смены в день → день просто не присылать. Пустой `days` → экран «Нет данных».

### `GET /api/devices/timesheet/wishes?month=2026-11` и `POST /api/devices/timesheet/wishes`
```json
// GET и ответ POST
{ "month": "2026-11", "status": "open|sent|approved|rejected|closed", "days": ["2026-11-08"],
  "editable": true, "limit": 4, "deadline": "25.10" }
// POST (идемпотентно: заменяет пожелания сотрудника на месяц)
{ "month": "2026-11", "days": ["2026-11-08", "2026-11-15"] }
```
Правила (будущие даты, лимит, срок приёма) проверяет сервер; нарушение → 4xx с `message`. `editable=false` → приложение блокирует выбор. Пока метод не готов (404), экран показывает ошибку, а не «отправлено».

### `GET /api/devices/breaks/recommendation`
```json
{ "from": "14:30", "to": "14:50", "reason": "затишье по чекам в это время" }
```
Нет рекомендации → `{ "recommendation": null }` (приложение: «Рекомендаций пока нет»). Фиксации факта перерыва на кассе нет.

### `GET /api/devices/shift/summary`
Итоги текущей смены точки. Все поля необязательные; приложение показывает только пришедшие.
```json
{ "receipts": 84, "revenueRub": 36680, "avgReceiptRub": 437, "drinksSharePct": 78,
  "hourly": [ { "hour": 8, "revenueRub": 1200 } ], "top": [ { "name": "Капучино", "qty": 18 } ] }
```
График рисуется только при ≥ 2 точках `hourly`. Если метода нет или `receipts` не пришёл — экран показывает локальный счётчик этого терминала (чеки, пробитые на кассе после установки 4.9.1), с подписью источника.

### `GET /api/devices/shift/team`
```json
{ "people": [ { "name": "Иванов Пётр", "role": "Кассир", "receipts": 42, "revenueRub": 18340 } ] }
```
`receipts`/`revenueRub` необязательны. Без рейтингов и сравнений.

### `POST /api/devices/shift/ops-log` (необязательно, приложением пока не вызывается)
Копия внесения/изъятия для вашей отчётности: `{ "type": "in|out", "sumRub": 1000, "comment": "...", "at": 1730000000 }`. Фискальный документ создаёт Эвотор.

## F. Номер заказа и очередь
Номер to-go (01…99) и очередь бариста **ведутся локально на кассе** (SharedPreferences) — бэкенд не нужен. Нумерация начинается с 01 при новой смене Эвотора (номер смены из `SystemStateApi`), а если Эвотор номер не отдал — с 00:00. Это не номер фискального чека.
Опционально: поле `isFood: true|false` в `products[]` каталога — явный признак еды для рекомендаций (иначе по метке `#food`, группе/категории «Еда/Выпечка/Десерты» и словам в названии).

## G. Чего не делать
- Не фискализировать «второй» чек. Не создавать новый товар Эвотора на каждый sync (`articleNumber = sc-<id>`).
- Не отдавать секреты в APK. Не считать на бэкенде то, что известно только Эвотору (остаток наличных в кассе, состояние ККТ).
- Не возвращать демо-данные «чтобы экран не был пустым».
