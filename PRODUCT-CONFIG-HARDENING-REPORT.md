## 2. Исправленные дефекты

1. **Обход через «+» на плитке** (`MainActivity` onInc): товар без «выбора по каталогу» добавлялся в корзину напрямую, минуя запрос конфигурации → обязательное молоко можно было не выбирать. Теперь путь идёт через `openProduct`.
2. **Отсутствующий `productId` подставлял ожидаемый** (`optInt("productId", expectedProductId)`) → конфигурация чужого/битого ответа считалась своей. Теперь отказ, если поля нет/не число/≤0/не совпало.
3. **Отсутствующий `storeUuid` принимался** (`storeUuid.ifEmpty { expectedStoreUuid }`) → конфигурация другого магазина могла примениться. Теперь отказ.
4. **Пустая схема молока при `required=true`** не блокировала продажу (`configOpts` возвращал пустой список). Теперь блокер «Нет схемы молока для объёма — продажа запрещена».
5. **Смена объёма в окне** не пересчитывала блокеры конфигурации: схема могла относиться к другому размеру. Теперь `configBlocked` пересчитывается в `onVariantChanged` и повторно проверяется в обработчике «В чек».
6. **Устаревший кэш** считался достоверной конфигурацией без ограничения по возрасту. Теперь TTL 24 ч.

## 3. Ответы по проверяемым путям

| Путь добавления в чек | Защита |
|---|---|
| тап по плитке | `openProduct` → запрос → окно/добавление |
| «+» на плитке | `openProduct`, пока сервер не подтвердил «схем нет» |
| повторный тап по карточке | `configLoadingUuid` |
| «+» у строки в корзине | количество, состав опций не меняется |
| «Повторить» (`Cart.repeatLast`) | повтор уже проверенной конфигурации; **не** валидируется заново (ограничение п.6) |
| 404 / 403 / 500 / таймаут / битый JSON | окно, прямое добавление запрещено |
| кэш другого товара/точки | отклоняется парсером (productId/storeUuid) |
| кэш старше 24 ч | не используется |

Цена и наименование платного молока/добавок: в чек идут по `productUuid` из каталога,
`SellLauncher` берёт позицию из номенклатуры Эвотор (`InventoryApi.getProductByUuid`),
цена терминала приоритетна, расхождение с каталогом только логируется (`price_mismatch`).
Опция, которой нет в номенклатуре, в окне недоступна (`available=false`), поэтому цена из
ответа конфигурации в чек попасть не может.

## 6. Оставшиеся ограничения и риски

1. **Терминал не проверялся**: реальный чек (обычное молоко, платное молоко, добавка), `logcat -s SC_TOP`,
   поведение при закрытии чека в POS — только на Эвотор.
2. **Backend-маршрут** `GET /api/devices/products/{id}/configuration` в этом репозитории не проверялся;
   на 404 касса работает по каталогу (окно, без молчаливого добавления).
3. **URL не подменяется в тестах**: `ProductConfigApi.fetch` использует `BuildConfig.API_BASE_URL`
   и `android.net.Uri`, поэтому HTTP-коды проверяются на уровне результата (`FetchResult`) и политики,
   а не через локальный сервер в unit-тестах.
4. **UI-тестов нет** (нет Robolectric/Espresso): логика вынесена в чистые `ConfigOptsMapper` /
   `ProductConfigGuard` / `DrinkConfig`, но сам клик «В чек» тестами не покрыт.
5. **`Cart.repeatLast`** восстанавливает прошлый чек без нового запроса конфигурации.
6. **Требуется корректная конфигурация на backend**: если объём не связан с `evotorUuid`,
   продажа размера блокируется сообщением «Объём не опознан: выберите другой размер».
7. **Перегрузка `DrinkConfig.receiptLines(variant, milk, additions)`** не используется в боевом пути
   (только тесты); цена платного молока в ней 0 — фискальную цену всё равно даёт номенклатура по uuid.
8. Изменения **не отправлены** в GitHub и APK **не опубликован**.
