# Отчёт: видимая диагностика схем в окне товара (5.2.21)

Версия: **5.2.21-config-diagnostics / versionCode 147**. База: `20ab1c7`.
Push, публикация APK, backend и серверный API — не менялись.

## 1. Зачем

Владелец не может снять `logcat` с терминала, поэтому причина «в окне виден только объём»
раньше была невидимой. Теперь она печатается текстом прямо под блоком выбора
(`ConfigDiagnostics.hint`), плюс в лог `config_hint <uuid> text=…`.

| Причина | Что видит кассир |
|---|---|
| каталог не сопоставил товар | «Схема не запрошена: товар не сопоставлен с сервером (нет productId). Обновите каталог.» |
| нет UUID точки | «Схема не запрошена: не определён UUID точки.» |
| маршрута `/configuration` нет на backend | «Сервер не отдаёт конфигурацию товара (HTTP 404) — окно работает по каталогу.» |
| ответ из кэша, схем нет | «Схема не назначена (используются сохранённые данные с сервера).» |
| сеть/ошибка сервера | «Схема не получена: сервер недоступен. Проверьте связь и повторите.» |
| схемы есть, объём не связан с `evotorUuid` | «Для этого объёма схема не назначена (объём не сопоставлен с сервером).» |
| схема есть, опции недоступны | «Схема есть, но опции недоступны (нет товаров Эвотор).» |
| схемы нет вовсе | «Молоко и добавки не назначены: у товара нет схемы на сервере.» |

Подсказка молчит, когда опции уже есть (молоко/добавки) или в окне топпинги каталога.

## 2. Дополнительно закрыт тихий обход

`ProductConfigGuard.appliesTo(cfg, cardUuids, cardProductId)`: если backend прислал схемы,
но не связал объёмы с `evotorUuid`, конфигурация всё равно относится к карточке (совпадение
`productId`) → продажа блокируется «Объём не опознан», а не уходит молча по каталогу.
Конфигурация **без** схем (только объёмы) каталог не блокирует.

## 5. Ограничения

1. На терминале не проверялось (только сборка и unit-тесты).
2. Подсказка объясняет причину, но **не создаёт данные**: если схемы нет на сервере/в каталоге,
   молоко не появится — нужно завести схему в админке или включить маршрут конфигурации.
3. Правило `appliesTo` может блокировать продажу размера, если backend не связал объёмы
   с `evotorUuid` (это осознанно: иначе обязательное молоко обходится).
4. Backend не менялся.
