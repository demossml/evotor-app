# 4.2.0-cashier-ux (versionCode 65) — редизайн UX кассира

Основание: отчёт «UX-аудит кассового APK и план редизайна» (находки F1–F20). Собрано на основе исходников 4.1.1 (versionCode 64).
**Сборка в этой среде не выполнялась** (нет Android SDK): проверен только синтаксис Kotlin. Перед выкладкой — сборка в Android Studio и смоук-чеклист на реальном ST5 (см. ниже).

## F2 — НЕ решено, нужно решение владельца

В 4.1.1 подарочная чашка доступна для **любого** товара (`freeEligible = true`), скидка применяется к **самой дешёвой единице** чека. Это расходится с `docs/BARISTA-FLOW-V2.md` («подарок только при явных метаданных»).
Поведение **сохранено** (иначе подарки внезапно пропадут у гостей), но теперь оно видно кассиру: в окне «К оплате» написано, какая позиция и на сколько будет скидка.
Чтобы отключить подарки до появления данных о праве товара: сборка с `-PFREE_CUP_ALL_PRODUCTS=false` (поле `BuildConfig.FREE_CUP_ALL_PRODUCTS`). Источник права товара по Evotor UUID (backend/админка) — отдельная задача.

## Общий расчёт скидки

Арифметика вынесена без изменений в `data/DiscountCalc.kt` и используется и `DiscountIntegrationService`, и окном «К оплате» — предпросмотр совпадает с чеком.

## Не тронуто (контракты)

`extras.sc` v2 `{v,c,ts,op,free,cb}`; `POST /api/devices/loyalty/resolve` и таймауты 4 с / 6 с; MAIN + EVOTOR intent-filter; `DiscountIntegrationService` (событие receiptDiscount, логика та же); `ScannerReceiver` и внутренний broadcast; `usesCleartextTraffic=false`; backend — источник баланса; безопасный offline (QR без бонуса, голый номер отклоняется); portrait. Новых зависимостей нет. `versionCode` 64 → 65.

## Не сделано / ограничения

- Добавки (модификаторы), F10: способ передачи в чек Эвотор в найденной документации не описан — UI не добавлялся.
- Автоопределение успешной оплаты: callback фискализации в SDK нет, подтверждение остаётся ручным (но не диалогом).
- Живой обратный отсчёт резерва: сейчас значение фиксируется при открытии окна «К оплате».
- Реальный размер экрана ST5 в dp и способ сканирования QR на ST5 не подтверждены.

## Смоук-чек на терминале

1. Скан QR; ввод короткого номера; неверный номер (красная плашка); выключить сеть (жёлтая плашка, QR без бонуса, голый номер отклонён).
2. Каталог: загрузка, поиск, добавление, «К оплате» видна без прокрутки при 20+ позициях.
3. Корзина: −/+/×; «Очистить» только через «Ещё» с подтверждением.
4. Подарок и кэшбэк: окно «К оплате», итог = итогу в чеке Эвотор; `extras.sc` в SELL.
5. Возврат с оплаты: «Чек пробит» очищает всё; «Не оплачено» возвращает заказ; перезапуск приложения на экране ожидания.
6. Скан при активной карте: диалог «Заменить карту?».
7. Время отклика тапа по плитке и память на ST5 (1 ГБ).
