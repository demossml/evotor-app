# IMPLEMENTATION — одно окно клиента вместо цепочки диалогов

Промпт: `PROMPTS-CASHIER-CLIENT-SCREEN-SEQUENTIAL.md` (C00–C06) · 28.10.2026
Сборка: **5.2.9-client-screen / versionCode 134** · тесты **269 / 0**

## 1. Что было

После скана касса могла показать до трёх разных окон подряд, а на каждый повторный скан
(включая тот же QR) спрашивала «Заменить карту?». Логика льготы была размазана по двум
независимым листам: «Льгота гостя» (после карты) и «Льготность» (из корзины), причём второй
открывался и автоматически перед оплатой.

## 2. Что стало

| Было | Стало |
|---|---|
| `AlertDialog «Заменить карту?»` на каждый скан | Вопрос удалён: тот же код — тихое обновление, другой код — новая сессия (`CardReplaceRule`) |
| Лист «Льгота гостя» после карты | Окно клиента (единое) |
| Лист «Льготность» из корзины (271 строка) | Удалён, его содержимое вошло в окно клиента |
| Чип карты в шапке вёл на экран привязки | Открывает окно клиента (при привязанной карте) |
| Авто-окно перед оплатой | Нет: перед оплатой только отправка позиций |

**Окно клиента** (`openClientScreen`): маска карты и прогресс, статус подарка, варианты
«Без льготы / Бесплатный напиток / ваучер / списать кэшбэк» (взаимоисключающие), кнопка «К заказу».
Открывается после `resolve` (один раз на карту), по тапу на карту в шапке и по «Изменить льготу»
в корзине. Контент в скролле, кнопка закреплена — как в 5.2.5.

## 3. Acceptance

```
[x] Скан → одно окно клиента, не 2–3 AlertDialog
[x] Тот же QR повторно → нет «Заменить карту»
[x] Другой QR → новая сессия + ClientScreen
[x] Ручной вход в клиента с заказа (чип карты, «Изменить льготу»)
[x] Gift/voucher только из ClientScreen
[x] Pay без повторного prompt
[x] Fiscal path (1₽ / priceWithDiscount) не откатан — FiscalCalc/FiscalLines не тронуты
```

## 5. Решения

1. **Кэшбэк оставлен в окне клиента** (только когда ваучеров нет — иначе три выгоды в одном
   списке путают). Промпт перечислял подарок и ваучер, но выкидывать списание кэшбэка значило бы
   убрать работающую функцию.
2. **Замена карты без подтверждения** на другой код: промпт требует «новая сессия + ClientScreen»,
   лишний вопрос — это и был раздражающий диалог.
3. **Подарок применяется к самой дешёвой подходящей единице** на момент расчёта (как в
   `DiscountCalc`/`FiscalCalc`), а не к «следующей добавленной» — иначе сумма «прыгала» бы
   при каждом добавлении позиции.

## 6. Не проверено

Терминал: как окно выглядит на 5″/10″, поведение при скане новой карты во время открытого окна,
скролл списка из 5 ваучеров. Логика покрыта unit-тестами, вёрстка — нет.
