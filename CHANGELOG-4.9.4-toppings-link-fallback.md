# 4.9.4-toppings-link-fallback (versionCode 103)

## Исправление схем добавок на кассе

- Каталог 6.7 больше не отбрасывает продукт только потому, что API не вернул `evotorUuid` для основной позиции.
- Сначала используется точное совпадение Evotor UUID; если UUID отсутствует или отличается между точкой и backend, используется точное нормализованное имя товара.
- Fallback по имени применяется только для уникальных имён из ответа API; неоднозначные имена игнорируются, чтобы не привязать схему к неправильному товару.
- Кэш обогащения сохраняет fallback-индекс, поэтому схемы остаются доступны после перезапуска и при временном отсутствии сети.
- Добавлена обработка флага `required` для опций из схемы: доступные обязательные добавки предварительно выбраны и не снимаются случайным повторным нажатием.
- Диагностика `SixthCup` теперь показывает количество совпадений по UUID и по имени.

## Важно

Платные добавки по-прежнему могут попасть в чек только при наличии реального UUID товара в каталоге Эвотор. Если в диагностике `withToppings > 0`, но `sellableToppings = 0`, нужно проверить связи добавок с товарами/UUID на стороне backend и синхронизацию каталога.
