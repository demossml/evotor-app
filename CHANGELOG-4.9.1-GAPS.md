# 4.9.1 (versionCode 98) — закрытие пробелов аудита

## P0
1. **Номер заказа + «Очередь»** — `data/OrderQueue.kt` (чистая логика), `data/OrderQueueStore.kt` (SharedPreferences).
   - При «Чек пробит» выдаётся номер 01…99; показан крупно на экране «Оплачено» вместе с составом.
   - Правило сброса одно: новая смена Эвотора (`SystemStateApi.getLastSessionNumber`), если номер смены неизвестен — календарные сутки (00:00). После 99 — снова с 01, занятые номера пропускаются.
   - Экран «Очередь»: «В работе» (номер, время, состав, «Готово»), «Готовы» («В работу»); готовые скрываются через 15 мин, забытые — через 12 ч. Индикатор в шапке (часы + номера в работе, галочка + готовые) открывает очередь; кнопка «Очередь бариста» на экране «Оплачено».
2. **Еда для рекомендаций — по данным, не по эвристике** — `data/FoodRules.kt`, поле `CatalogProduct.isFood`: метки `#food`/`#nofood`, флаг backend `isFood`, группа/категория (Еда, Выпечка, Десерты…), слова в названии. Комбо = еда есть. Upsell только если еды в корзине нет. Logcat: `hasFood=… upsellShown=…`.
3. **Опции / ±**: sheet показывается при наличии схемы (условие по evotorUuid не возвращалось), опция без uuid — «нет в кассе». Исправлено: на плитке с несколькими размерами «×N» и «−» теперь считают все размеры (`Cart.qtyAny/decAny`). В upsell ± работает по uuid позиции.
