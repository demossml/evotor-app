## Что нового относительно 160
1. **«Подтянуть в чек» работает**: позиции предзаказа добавляются в текущую корзину через
   `InventoryRepository.load()` (номенклатура терминала) + `Cart.add(CartLine(...))` — тот же
   механизм, что у ручного добавления. Цена — из номенклатуры, не из `estimateTotal`.
2. **markPaid после успешной продажи**: в `MainActivity.onResume` (ветка «чек закрыт») один раз
   вызывается `OrderApi.markPaid(orderId)` — только если предзаказ реально лежал в этом чеке
   (проверка по `cartKey` `pre:<orderId>:…`).

## Smoke на кассе
1. Создать предзаказ на backend (или взять тестовый oid).
2. Скан order QR (`ord1.…`) или «Заказы» → ввод 6 цифр → экран заказа.
3. «Принять» (статус `accepted`) → **«Подтянуть в чек»** → тост «В чеке: N поз.» и возврат на кассу;
   позиции видны в корзине с ценами терминала.
4. Оплатить чек → в `logcat` строка `preorder_paid order=<id> status=paid`;
   `GET /api/devices/orders/active` больше не содержит заказ.

## Known issues
1. Позиции без `evotorProductUuid` не добавляются: тост перечислит их имена («Без UUID Эвотора: …»).
   Товара нет в номенклатуре точки → «Нет в кассе: …».
2. Модификаторы **не** становятся фискальными позициями (у них нет uuid Эвотор): их текст идёт
   в рецепт строки, `sendToReceipt=false` не печатается. Если нужно пробивать сироп отдельной
   позицией — требуется uuid в ответе backend.
3. Ошибка `markPaid` (нет сети) только логируется: фискальный чек не откатывается, заказ остаётся
   неоплаченным на backend → повторить вручную в админке/после следующей продажи этого заказа.
4. Backend-эндпоинты `/api/devices/orders/*` с этой машины не проверялись.
5. Экран заказов и печать выбора — без изменений с 160.
